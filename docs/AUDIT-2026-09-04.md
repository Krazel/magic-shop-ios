### MS-AUD-001 - Purchase and onboarding persistence are not atomic

Initial evidence: MagicShop/App/AppModel.swift, original lines 148-149, called
engine.confirm before persistEngineState. A write error left engine changed
while the published state and placement route remained unchanged. Cancelling
then published engine.state at original line 137, exposing a purchase after
the UI had reported failure. Moving the same draft and retrying could purchase
another fixture with the same ID. Onboarding used the same mutation-before-save
sequence at original lines 60-61.

Correction reviewed: MagicShop/Core/Persistence/GameSession.swift, lines 15-20,
copies the engine, applies the command to that candidate, saves its state and
only then assigns the live engine. AppModel.submitOnboarding and
confirmCurrentPlacement publish state only after commit returns successfully.
The live engine and UI therefore remain unchanged when a command or save throws.
AppModel owns the session on MainActor; the current integration does not expose
a concurrent session writer.

Declared regression tests reviewed:
- GameSessionTests.testFailedPurchaseSaveLeavesMoneyAndFixturesUntouchedAndCanRetry
- GameSessionTests.testFailedOnboardingWriteDoesNotCompleteOrPersistName
- GameSessionTests.testInvalidCommandDoesNotWrite
- AppModelTests.testPurchaseFailureCancelAndRetryNeverChargeTwice

Disposition: no remaining P1 observed in this correction. Execute these tests
through the authoritative macOS gate; do not describe them as passed merely
because they are declared.

### MS-AUD-002 - Failed reads silently become writable new games

Initial evidence: AppModel.swift, original line 26, used try? load followed by
.initial. Decoding or filesystem errors were indistinguishable from a missing
save. Completing onboarding could consequently overwrite the existing file.
Failure to resolve Application Support also silently used an in-memory store.

Correction reviewed: AppModel.restoreSavedSession, lines 26-40, keeps session
nil when store creation or reading fails and displays an inline retry message.
submitOnboarding retries reading without saving when session is absent;
openBuild, beginPlacement and confirmCurrentPlacement guard the session.
The original file is not replaced through those paths. A successful retry
restores the saved state and route before accepting another command.

Declared regression tests reviewed:
- GameSessionTests.testUnreadableSaveIsPreservedAndDoesNotStartNewSession
- AppModelTests.testLoadFailureBlocksNewGameWritesAndCanRetryRead

Disposition: no remaining P1 observed in this correction. Missing-file startup
must remain valid; malformed or unsupported saves must remain preserved.
A future recovery screen is not implicitly approved by this audit.

### MS-AUD-003 - Plate and invisible hitmap use different obstacle positions

Initial evidence: WorldMap.swift, lines 186-192, defines blockers retained from
the modular environment. ShopScene.swift, lines 5-7 and 29-47, maps a centered
square onto the current 853 x 1844 plate.

At the source image aspect ratio, the current logical square is 571.64 pixels
wide, spanning approximately x=140.68..712.32 and y=614.05..1185.69 in PNG
coordinates. Visual landmark positions map as follows:

| Landmark | Approximate PNG position | Cell computed by current geometry | Authored blocked cell |
| --- | --- | --- | --- |
| Paper scraps | 638, 1030 | 9, 2 | 8, 2 |
| Broken boards | 644, 921 | 9, 5 | 9, 4 |
| Plaster rubble | 193, 920 | 1, 5 | 1, 4 |

Landmark coordinates are visual estimates, not automated segmentation.
They demonstrate that testing the existing metadata against itself does not
verify alignment with the displayed art. Sprite placement can be accepted on
visible debris while apparently empty space is rejected.

Disposition: open M2 calibration gap by project-owner decision. Review the
current master/plate and comparable simulator captures before changing the map.
Preserve the direct background plate and invisible 11x11 map. Address existing
persisted maps deliberately: changing WorldHitMap.starter alone does not update
an existing saved world, and existing player fixtures must not be discarded.

### MS-AUD-004 - Shelf art and logical footprint diverge on rotation

Initial evidence: ShopScene.swift, lines 178-189, sizes the shelf using an
already-rotated footprint and then rotates the sprite again. At east/west, the
logical footprint is 1x2, while the sprite ends approximately 1.86 cells wide
and 0.93 high. At south, the perspective drawing is upside down. North sizing
uses a 1.348 width/height ratio although the source PNG ratio is about 0.735,
flattening the approved vertical two-compartment shelf.

Disposition: open M2 art/orientation gap by project-owner decision. Review
masters and comparable captures, then use uniform art scaling and a camera-
appropriate orientation strategy. Do not invent final directional art or
reinterpret the approved scene without the applicable visual review.
Validate all allowed wall orientations, foot contacts, stock sockets and
occlusion against the logical footprint.

### MS-AUD-005 - Pan distance is not stable under zoom

Initial evidence: ShopSceneContainer.swift, original line 77, passed screen
translation.y directly to WorldCameraState.panVertically. The screen/world
transform divides visible displacement by camera.zoom. A 100-point drag
therefore moved the world by approximately 153.85 screen points at zoom 0.65
and 80 points at zoom 1.25.

Correction reviewed: line 77 now passes translation.y multiplied by
cameraState.zoom. This restores equal finger/world screen displacement away
from the clamp boundary.

Disposition: corrected mathematically in source. The existing camera tests
check clamps but do not exercise the recognizer-to-camera integration. Verify
screen displacement at zoom 0.65, 1.0 and 1.25, then check pinch, tap placement,
safe-area layout and natural vertical movement on iPhone. Pinch anchoring and
motion feel are runtime QA concerns, not established by this algebra.

### MS-AUD-006 - Unsupported saves are silently downgraded

Initial evidence: GameState.swift, original line 43, ignored the stored schema
version and assigned the current version during every decode. A newer save
could lose unknown fields when an older build subsequently saved it.

Correction reviewed: current GameState.swift, lines 52-55, reads the version
and rejects versions outside 1...currentSchemaVersion. The current file also
contains schema 3 and integrity/commerce work in progress.

Disposition: the specific future-version acceptance defect is corrected in
source. This focused audit did not validate the unfinished commerce model or
the full integrity validator. Verify future-version rejection preserves exact
file bytes and legacy schema 1/2 migrations retain name, balance, fixtures,
floor styles and hitmap.

## Product and architecture risks for the next slice

These were gaps in the initial first slice, not claims about the commerce
implementation currently being written.

- Economic recovery: ten $50 tables consume the entire initial $500, leaving
  no money for paid stock. The playable loop needs a documented recovery rule
  and tests for zero funds, rather than a permanent dead end.
- Reachability: protecting only the entrance cell does not protect its exit
  or routes to displays. Decide customer access using the same invisible map
  and dynamic fixture occupancy; test a sealed doorway and an enclosed display.
- Transactional days: stock identity, display slots, sale events, day progress
  and income must survive repeated commands, save failures and restart without
  duplicate purchases or rewards. Reuse the session transaction boundary.
- Phase ownership: Build, Stock, Open and summary transitions must have explicit
  domain rules, including which edits are allowed during a day. UI disabling
  alone is insufficient.
- Scope discipline: the initial runtime has no stock, customers, day summary,
  repairs, decoration or expansion interface. New major visual states need
  their own complete approved iPhone references; structural work may proceed
  while that approval is pending.

XCTest. The local test-macos.sh additionally runs swift test, while the inspected
CI workflow did not. Exact-head CI results and device IPA verification belong
to the root integrator; the audit has not inferred them from old Brain records.

Brain project record contains historical contradictory entries about modular
assembly and pending approvals. Current repo instructions and the owner's
explicit direct-plate decision govern this work. Update current status without
destroying historical decisions or approved images.
